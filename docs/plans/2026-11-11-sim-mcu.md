## Goal
`rccar_sim_mcu` is a ROS 2 Python package that replaces the ESP32 at the device boundary. The real `car.launch.py sim:=true` (supervisor + `mcu_bridge`) runs against it with no change.

## Design (source: pinned `firmware/esp32/src/main.cpp`, FW 0.3.0)
### `rccar_sim_mcu/model.py` (pure Python, no rclpy, injected time `now_ms`)
- `Config`: the firmware `Config()` defaults (main.cpp:63-94). Examples: `maxSteerDeg` 25, `headingGain` 1.0, `speedLimit` 0.30, left 1800, right 1200, timeout 300 ms, accel 2.0, `controlHz` 100.
- Drive math ports: `heading_to_steer_deg`, `steer_deg_to_us`, `throttle_to_us`. Rounding and clamps are the same as the firmware (`lroundf`).
- `McuModel`:
  - `on_drive(heading_rad, throttle, now_ms)`: a non-finite value is dropped. The heading is clamped to ±180°, the throttle to ±1.
  - `step(now_ms)`: one `controlTask` tick. Failsafe (armed and stale > timeout: disarm + FAILSAFE), slew (`accel / control_hz`; disarm sets 0 at once), `u = speedOut * speedLimit`, double-tap reverse (Forward, Brake, Gap, Reverse), RAW override.
  - `handle_line(line, now_ms)`: the full `handleLine` grammar. The CFG line is byte-exact (main.cpp:366-373). The `setKey` clamps are exact. The service refuses `D` with the firmware string.
  - Events: READY `fw=0.3.0` on connect and reboot; FAILSAFE `command timeout -> disarmed`, then DISARMED; ARMED and DISARMED on change.
  - `reboot()`: config goes back to the saved config (SAVE keeps it in memory, as NVS), disarm, READY.
- Rangefinder stub: no return, so `+inf`, frame `rangefinder_link`. The `sim-gz` PR supplies real ranges.

### `rccar_sim_mcu/node.py` (thin node `rccar_mcu`)
- Interfaces: the `/rccar/mcu/*` rows and `/rccar/rangefinder/range` of the car `docs/sensor_contract.md`, with the same types and QoS.
- A control timer at `control_hz` on the node clock (`use_sim_time` is honored; one clock).
- Sim-only fault services in the private namespace, outside `/rccar/`: `~/fault_drop_drive` and `~/fault_reboot`.
- The node never publishes `/rccar/mcu/drive`.

### Tests
- Unit: pure pytest for the model.
- Golden vectors: a g++ harness compiles the drive math from the pinned `main.cpp` and compares a vector grid with `model.py`.
- Drift: the test parses `main.cpp` for the defaults, the CFG format, the `setKey` keys and clamps, the event texts and the error strings. Every command from `firmware_commands(load_tuning(tuning.toml))` must give no `ERR`.
- Launch tests with the real car nodes (no Gazebo):
  1. Tuning push: after READY, `GET` shows the `tuning.toml` values (maxdeg 30.0, gain 2.00, limit 0.70, left 1200, right 1800), not the firmware defaults. The bridge never sends ARM.
  2. Failsafe: arm, stream, drop the drive, then FAILSAFE and DISARMED, then the supervisor is latched. Reboot while armed: the supervisor latches and the bridge pushes the tuning again.
  3. Only `supervisor` publishes `/rccar/mcu/drive`.
- Repo test `tests/test_drive_publisher.py`: no `rccar_sim_*` code publishes `/rccar/mcu/drive`.
